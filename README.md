# 福知山公立大ポータル（自動ログインアプリ）

Electron（Chromium）ベースのインストール型デスクトップアプリです。
福知山公立大学のポータルサイトに自動ログインし、そのままホーム画面を表示します。

## 主な仕様

- 初回起動時にログインID・パスワードの入力画面を表示し、入力内容をOSレベルの暗号化（`safeStorage`）で端末内に保存します。
- 2回目以降の起動では、保存済みの情報を使ってログインフォームへ自動入力・自動送信します。
- ポータル内で外部サービス（WebClass等）を開く際に発生する別ウィンドウ（ポップアップ）を抑制し、アプリ内の新しいタブとして開いて自動的にそのタブへ切り替えます（`setWindowOpenHandler` でポップアップ生成をすべて「新規タブを開いて切り替える」処理に置き換え）。ポータルのタブは閉じられないようにしてあり、WebClassなどのタブはタブの×ボタンでいつでも閉じられます。
- ウィンドウ左上に「戻る」「進む」「再読み込み」「ホーム」ボタンと、その右側にタブバーを表示します。「ホーム」ボタンはポータルのタブに切り替えたうえで、ポータルのトップURLへ移動します。タブを右クリックすると「複製」「閉じる」メニューが表示されます（ポータルのタブは閉じられないため「閉じる」は無効表示になります）。
- ツールバー右端の歯車アイコン（設定ボタン）から、保存済みのID・パスワードを消去して入力し直せます（パスワード変更時など）。
- ツールバーの時計アイコン（履歴ボタン）から、これまでに閲覧したページの履歴（タイトル・URL・日時）を一覧表示できます。項目をクリックするとそのページに戻れます。ログインページ自体は履歴に残りません。「履歴を削除」ボタンで全件消去できます。
- 設定（歯車）ボタン→「このアプリについて」から、バージョン・非公式ツールである旨・著作権表示を確認できます。表示内容は `renderer/about.html` を編集することで自由に変更できます。
- ページ内で右クリックすると、状況に応じたメニューを表示します。
  - 通常の場所（文字選択なし・入力欄以外）：「戻る」「進む」「再読み込み」「名前を付けて保存...」
  - 文字を選択して右クリック：「コピー」と、選択した文字列でOSの既定ブラウザからGoogle検索を開く項目（入力欄内であれば「切り取り」「貼り付け」も表示）
  - 入力欄（テキストボックス等）を選択なしで右クリック：「貼り付け」
- **F5** キー（または **Ctrl+R** / macOSは**Cmd+R**）で、現在表示中のタブを再読み込みできます（再読み込みボタンと同じ動作）。
- GitHub Releasesを使って自動アップデートを配布・確認できます（`electron-updater` 使用）。詳細は下記「アップデートの配布について」を参照してください。

## セットアップ（開発・動作確認）

Node.js（18以上推奨）がインストールされた環境で実行してください。

```bash
npm install
npm start
```

## インストーラーの作成

`electron-builder` を使ってインストール型パッケージを作成します。

```bash
# Windows用インストーラー（.exe / NSIS）
npm run dist:win

# macOS用（.dmg）
npm run dist:mac

# Linux用（AppImage）
npm run dist:linux
```

作成された成果物は `dist/` フォルダに出力されます。

### アイコンについて

`assets/icon.ico`（Windows）、`assets/icon.icns`（macOS）、`assets/icon.png`（Linux、512x512推奨）を配置すると、
インストーラー・実行ファイルのアイコンに加えて、**ウィンドウのタイトルバー左上に表示されるアイコン**にも自動的に反映されます
（`main.js` が起動時に `assets/` 内のファイルを自動検出します）。

現在 `assets/` フォルダは空のため、何も配置しないと、タイトルバーにはOS標準のアイコン（Windowsの場合は既定のプログラムアイコン）が表示されます。
大学のロゴなどを表示したい場合は、上記のファイル名で `assets/` フォルダに配置し、アプリを再起動してください（`npm run dist:win` でビルドし直す場合も同様に反映されます）。

## アップデートの配布について

`electron-updater` を組み込んでおり、**GitHub Releases** を使ってアプリの自動アップデートを配布できます（Windows/NSIS向け）。

### 仕組み

- アプリ起動時に、設定した GitHub リポジトリの最新リリースを確認しに行きます。
- インストール済みより新しいバージョンがリリースされていれば、ダイアログで「ダウンロードしますか？」と確認します。
- ダウンロード完了後、「今すぐ再起動してインストール」を選ぶとその場で差分適用されます。
- ツールバーの設定（歯車）ボタンからも「アップデートを確認」で手動チェックできます。
- 開発中（`npm start`）はアップデート確認自体をスキップします。ビルドしてインストールしたアプリでのみ動作します。

### 事前準備

1. `package.json` の `build.publish` を、実際に使うGitHubリポジトリに書き換えます。

   ```json
   "publish": [
     { "provider": "github", "owner": "あなたのGitHubユーザー名", "repo": "リポジトリ名" }
   ]
   ```

2. GitHubで [Personal Access Token](https://github.com/settings/tokens) を発行します（`repo` スコープが必要）。

3. ビルド・公開を行う端末で環境変数 `GH_TOKEN` にそのトークンを設定します。

   ```bash
   # Windows PowerShellの例
   $env:GH_TOKEN = "発行したトークン"
   ```

### 配布手順

1. アップデートを配布するたびに `package.json` の `"version"` を上げます（例: `1.0.0` → `1.0.1`）。

2. 以下を実行すると、ビルドと同時に GitHub のリリースが自動作成され、インストーラー・`.blockmap`・`latest.yml` がリリースにアップロードされます。

   ```bash
   npm run release:win
   ```

   実行直後はGitHub上でリリースが「下書き（Draft）」として作成されるので、GitHubのReleasesページで内容を確認して公開（Publish）してください（下書きのままだとユーザー側からは検知されません）。

3. 公開すると、既にインストール済みのアプリは次回起動時（またはユーザーが手動確認したとき）に新しいバージョンを検知します。

### 注意点

- リポジトリが **プライベート** の場合、アプリ側にも認証情報が必要になり配布用途には不向きです。アップデート配布用のリポジトリは基本的に**パブリック**にしてください（アプリのソース自体を別のプライベートリポジトリで管理し、配布用だけパブリックにする運用も可能です）。
- コード署名をしていない実行ファイルは、初回インストール時にWindows SmartScreenの警告が出ることがあります。アップデート自体の動作には影響しません。
- macOS / Linuxでも自動アップデートを使う場合は追加設定が必要です（現状はWindows/NSISでの利用を主眼にしています）。
- ビルド専用に使いたい場合（GitHubへは公開したくない場合）は、これまで通り `npm run dist:win` を使ってください。こちらはリリースを作成・公開しません。

## 資格情報・履歴の保存場所

- Windows: `%APPDATA%\fukuchiyama-portal\credentials.dat`（ログイン情報）/ `%APPDATA%\fukuchiyama-portal\history.json`（閲覧履歴）
- macOS: `~/Library/Application Support/fukuchiyama-portal/`
- Linux: `~/.config/fukuchiyama-portal/`

保存前にOSの資格情報保護機能（Windows DPAPI / macOS Keychain / Linux Secret Service等）で暗号化されます。
該当機能が利用できない環境では、その旨をコンソールに出力し保存を行いません。

## ログインフォームの自動検出について

大学ポータルのログインフォームは、ページ内の「パスワード欄（`input[type="password"]`）」と、
その同じフォーム内にあるテキスト欄をログインIDの入力先として自動的に検出する方式にしています。
そのため、大学側でフォームの内部構造（name属性など）が変更されても、
パスワード欄が1つのフォームに存在する限り動作し続けやすい作りになっています。

万が一ログインに失敗し続ける場合は、同一セッション内で自動ログインの再試行を3回までに制限し、
無限ループを防止しています（アプリを再起動すると再度試行できます）。
